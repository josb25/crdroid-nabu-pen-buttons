firmware: nabu: report decoded pen side buttons in NT36523 v25

The CSOT NT36523 v25 pen-report formatter clears its button field even
though Dell PN7522W side buttons are decoded in the internal pen object.
The existing Linux input driver already maps that field to BTN_STYLUS
and BTN_STYLUS2.

Replace a same-length ten-byte instruction window to copy the decoded
button byte while preserving the adjacent battery value for the existing
branches. Update both shared ILM CRC copies and both cascade-header CRCs.
The decoded blob changes exactly nine code bytes and sixteen CRC bytes;
report size, layout and checksum code remain unchanged.

Only firmware/novatek_nt36523_fw01.bin.ihex changes. No driver fallback,
additional IRQ SPI reads, settings, Bluetooth or remapping changes.

Validation: generated output matches the tested binary SHA256; all section,
header and Intel HEX checksums pass. A temporary boot of the original
compiled kernel with only its 25 embedded firmware bytes changed recorded
1891 valid native pen packets over 60.2 seconds, balanced Linux transitions
for both buttons and Android primary/secondary/combined states, with no
extra internal-state reads or detected faults. All nine recorded stroke
starts matched native state within timestamp precision. No partition was
flashed. Tested on one Dell/CSOT/v25 device; other pens, suspend/resume,
charging and sustained use still require coverage before release inclusion.
